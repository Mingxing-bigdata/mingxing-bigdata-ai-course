# Concept Learner —— 概念深度学习工作流

把任何一个陌生概念，加工成一套"能学会、能复习、能查证"的学习材料。本文件是可复用流程：换一个新概念，按相同步骤产出同构的学习资料。

## 一、适用场景

**适用：**
- 用户想系统搞懂一个新概念（"帮我学一下 X"、"X 到底是什么意思"、"给 X 做一张概念学习卡"）。
- 复习/备考需要结构化知识点与自测题。
- 需要对两个相近概念做辨析（把每个概念各生成一份，再横向对比）。

**不适用：**
- 纯代码调试、报错排查（那是工程任务，不是概念学习）。
- 翻译、润色、生成整篇论文正文。
- 用户只想要一句话答案、不想要完整学习材料时，先给简述再询问是否需要完整版。

## 二、输入信息

| 字段 | 必填 | 说明 |
|---|---|---|
| 概念名称 | 是 | 要学习的概念；若有歧义先确认所指（如 Skill 指 Agent Skill，不是泛义"技能"） |
| 所属领域/出处 | 否 | 如"大数据课程""LLM 应用"，用于限定解释口径与举例 |
| 学习者背景 | 否 | 初学者/进阶，决定深浅与术语用量 |
| 输出语言 | 否 | 默认中文 |
| 输出格式与路径 | 否 | 默认 Markdown；本课程仓库须输出为 HTML 交互卡，存到 `learning-materials/`（命名如 `agent-memory.html`，与现有卡片同构） |

若信息不足影响质量，先问最关键的一项（通常只需确认概念所指），不要连环提问。

## 三、生成步骤

1. **澄清定位**：确认概念名称、领域、学习者背景；查清该概念在一手资料中的标准定义，不要凭印象编。
2. **一句话理解**：用大白话写"它到底是什么"，控制在 1-2 句，能让外行听懂。
3. **拆解核心机制或组成**：讲清"它由什么构成 / 内部怎么运转"，用列表或小图；只讲与理解强相关的部分。
4. **给一个具体应用场景**：挑一个具体的、可想象的场景，说明概念在其中起什么作用。
5. **辨析与边界**：列 2-4 组易混淆概念，用"区别是……；误用会……"句式；写明"什么情况下不该用它"。
6. **出自测题与选择题测验**：先写 3-5 道简答/判断自测题（附参考答案）；再写 5 道**选择题**，每题附解析，并做成可点击高亮（绿/红 + 实时计分）的**可视化交互**测验（纯前端 JS，同构于 `learning-materials/` 现有卡片）。
7. **核查资料来源**：见第五节要求；逐条核验后连同访问日期写入资料区。
8. **落盘输出**：本课程仓库按既有 HTML 卡片模板组织（学习目标 → 一句话理解 → 核心机制 → 应用场景 → 易混淆与边界 → 自测 → 选择题测验 → 资料来源），存为 `learning-materials/<概念>.html`；若用户只要文本版，再另存 Markdown 到 `concepts/`。

## 四、输出结构（模板）

```markdown
# 概念学习 · <概念名>

> 学习日期：YYYY-MM-DD · 生成方式：concept-learner 流程

## 学习目标
- （学完应能……）

## 一句话理解（我的解释）
（1-2 句大白话）

## 核心机制 / 组成
- 组成或机制要点，配必要示例

## 一个具体应用场景
（场景描述 + 概念在其中扮演的角色）

## 易混淆与使用边界
- vs 相近概念 A：……
- vs 相近概念 B：……
- 不该用它的情况：……

## 自测问题
1. Q：……（参考答案：……）
2. …

## 资料来源
- [标题](URL) —— 官方/出处说明（核验于 YYYY-MM-DD）
```

## 五、资料来源要求

- **须为权威学术资料**：本课程要求来源优先选用 arXiv 论文等公开学术一手文献（如 ReAct、Generative Agents、MemoryBank、RET-LLM、LLM Agent Survey 等），并标注核验日期；非学术官方博客/文档仅作补充，不得作为主来源。
- **不得伪造或臆造链接**：每条都必须真实存在且能打开；优先官方文档、论文、权威一手来源。
- **逐条核验并留痕**：写文件时在每条链接后标注核验日期；无法打开的链接一律删除或替换。
- **区分事实与观点**：机制性事实以一手资料为准；综述性观点标明出处。
- **不整段照搬**：解释用自己的话重写；确需引用原文时用引号并注明出处。
- 区域网络可能屏蔽个别官网（如 openai.com / claude.com 部分地区不可达）：优先选用可访问的官方链接；确需引用但本地打不开的，在资料区注明"存在但本机区域无法打开，未经逐条核验"，不得悄悄混入。

## 六、自检要求（交付前逐条核对）

- [ ] 概念定义与机制无事实错误，且与至少一个一手来源一致
- [ ] "一句话理解"是改写后的个人表达，未整段照搬任何来源
- [ ] 每条资料来源链接真实、与论断相关，标注了核验日期
- [ ] 应用场景具体可想象，不是泛泛而谈
- [ ] 辨析部分点明了"误用/不该用"的边界
- [ ] 自测题答案与正文自洽，无自相矛盾
- [ ] 含可视化选择题测验（点击高亮 + 解析 + 计分），且资料来源均为权威学术文献
- [ ] 文件按模板结构输出，路径与命名符合约定
