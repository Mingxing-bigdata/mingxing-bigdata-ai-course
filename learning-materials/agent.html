0 学习目标

  • 能说清 Agent 与“聊天式大模型”的本质区别
  • 能列出 Agent 的核心组成，并解释它们如何协作
  • 能判断“某个任务该不该用 Agent 来做”

1 一句话通俗理解（AI 生成）

Agent（智能体）就像一个会自己想办法干活的“数字员工”。你只告诉它“目标是什么”，它自己会拆解成步骤、决定调用什么工具（查资料、写代码、调接口），做完再看结果对不对——不对就换个办法重来，直到把活干完。整个过程中你不需要在旁边一步步教它。

2 核心机制 / 组成

业界公认 Agent ≈ 一个循环，由四类组件支撑：

目标 ─► LLM（大脑：理解＋推理） │ 规划（拆步骤 / 反思修正） │ 调用 工具（代码执行 · 搜索 · API · 文件） ▼ 观察结果 ─► 把结果放回上下文，继续推理 │ └──► 目标达成，输出
🧠 LLM（大脑）理解目标、生成计划与内容，类比：员工的大脑
📋 规划 Planning任务拆解与自我反思（如 ReAct），类比：想清楚先后顺序
🗂 记忆 Memory短期＝对话上下文；长期＝向量库/文件，类比：便签＋档案柜
🔧 工具 Tools代码执行、网页搜索、调 API、读写文件，类比：手脚与设备

工程化参考：LangChain 把 Agent 定义为 模型 + 工具箱 + 控制器(Harness)，由控制器驱动“模型在循环中调用工具直到完成”。

3 一个具体应用场景

让一个数据分析 Agent 处理：“找出某电商本月销售额异常的省份，并画一张图”。

  1. 规划：读文件 → 按省份汇总 → 与上月对比找异常 → 出图；
  2. 调用工具：用 Python 执行 pandas 统计、matplotlib 画图；
  3. 观察与修正：发现某省数据缺失，Agent 决定先做缺失值处理再继续；
  4. 完成：返回“异常省份 + 原因线索 + 图表”。

传统聊天机器人做不到第 2、3 步——它没有执行环境，也不会因“看到结果不对”而自我修正。

4 易混淆与使用边界

对比对象关键区别
vs 聊天机器人聊天式 LLM 只做“文本往返”；Agent 的关键是行动闭环（调用外部工具并基于结果继续）。会多轮对话 ≠ Agent。
vs 工作流 Workflow工作流是“预先写死步骤的管线”；Agent 由模型自主决定步骤。确定性任务用工作流更稳，开放式任务才值得上 Agent。
vs RAG 检索增强RAG 解决“记不住/不知道”的知识供给，是 Agent 可调用的手段之一，不互斥。

不该用 Agent 的情况：步骤完全固定的流程；对成本/延迟极敏感；输出必须严格可控；工具不可靠又无法验证。Agent 的代价是不可预测性——所以要给工具设计好接口、过程保持透明、必要时加入人审。

5 自测问题（先想再点开）

Q1：Agent 与聊天机器人的分界线是什么？
是否形成“规划 → 调用工具 → 观察结果 → 继续行动”的自主闭环。
Q2：Agent 四要素缺了“工具”，会退化成什么？
退化成“只会说不会做”的对话模型——有目标、无执行力。
Q3：每周固定跑一遍的报表任务，适合用 Agent 吗？
不太适合：属于确定性流程，用固定脚本/工作流更稳、更省成本。
Q4：为什么说 Agent 有“不可预测性”？
执行路径由模型自主决定，同样的输入可能走不同分支；需要透明展示规划、可靠工具与验证手段兜底。
