0 学习目标

  • 能解释“上下文（Context）”与“上下文窗口（Context Window）”的含义
  • 能说清上下文为什么是 Agent 记忆与行为的“天花板”
  • 能说出至少两种让上下文“装得下、用得好”的方法

1 我的解释（个人理解）

上下文就是 AI 这一次回答时能看到的全部材料资料——你提的问题、之前的对话、塞进去的文档都算。它不像人有长期记忆，每次都只看这一堆；这堆材料有上限，放太多就挤掉前面的，所以有时候答非所问，其实是上下文没给对或者装不下了。
✅ 以上为本人对概念的个人理解（已改写为自己的表达）。

2 核心机制 / 组成

🔁 无状态调用每次调用模型只看你这次给的内容；跨轮“记忆”由调用方把历史拼回上下文
🔢 Token 计量模型按 token 切分文本；上下文窗口＝一次最多容纳的 token 数
🧾 内容构成系统指令 + 用户消息 + 历史对话 + 检索片段(RAG) + 工具定义/返回
📍 位置效应对“中间段”的记忆弱于开头与结尾（Lost in the Middle），关键信息要讲究摆放
📏 窗口上限如 Claude 曾把窗口从 9K 扩到 100K token（约 7.5 万英文单词）
✂️ 超限处理内容超窗 → 截断 / 压缩摘要 / 先检索再塞入（上下文工程三板斧）

3 一个具体应用场景

场景：Agent 处理用户连续第 5 轮的提问。

此时调用方把前 4 轮对话、最新问题、以及刚执行完的 Python 工具输出一并放进上下文。模型“看到”之前的结论才能接话；如果历史太长，Agent 会先做一轮摘要，把旧对话压缩后只保留关键结论，再放进上下文——否则旧内容会把窗口撑爆。

这也解释了为什么 Context 是 Agent 记忆的天花板：短期记忆 ≈ 上下文里能装下的历史；装不下的要么遗忘（截断），要么搬运到外部长期记忆（向量库/文件），需要时再检索回来。

4 易混淆与使用边界

易混淆点澄清
上下文 ≠ 长期记忆上下文是一次性输入，会话结束即消失；长期记忆在外部存储里，靠检索回填。
上下文 ≠ 训练数据模型参数里学到的知识 ≠ 你这次放进窗口的资料，两者互不替代。
窗口大 ≠ 记得牢窗口只代表“能装”，不代表“每条都起作用”（中间段易被忽略、噪声会干扰）。
不该只靠加大窗口盲目塞入全部资料会抬高成本/延迟、降低准确性；应先检索 + 摘要 + 结构化组织。

5 自测问题（先想再点开）

Q1：为什么说“大模型没有记忆，只有上下文”？
模型每次调用都是无状态计算；跨轮“记忆”是调用方把历史重新作为输入放回上下文实现的。
Q2：Context Window 指什么？超限了怎么办？
一次调用最多容纳的 token 数；超限需截断、压缩摘要或检索后用。
Q3：为什么 Agent 的短期记忆上限≈上下文窗口？
Agent 能“想起来”的只有放回上下文的那些信息，窗口装不下就丢了。
Q4：检索（RAG）和上下文是什么关系？
RAG 先把相关资料检索出来，再把“命中片段”作为上下文的一部分喂给模型，让有限的窗口装更相关的信息。
