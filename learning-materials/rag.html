1 一句话通俗理解（AI 生成）

RAG（检索增强生成）就是给大模型配一个"开卷考试的小抄本"：答题前，它先去资料库里翻出最相关的几页，把内容贴到题目旁边，再据此作答。这样它就不必把全世界知识都"背"在脑子里，也能引用最新、私有的外部资料，少说瞎话。而"向量检索"是它快速翻到正确那几页的关键——把文字变成一串数字（向量），意思相近的文字在数字空间里也离得近，一算距离就找回来了。

2 核心机制 / 组成

① 用户提问自然语言问题
→
② 向量化问题 → embedding
→
③ 向量检索相似度取 Top-k
→
④ 拼进 Prompt问题 + 片段
→
⑤ 大模型生成带证据作答
📚 外部知识库（向量库）：事先把所有文档切块 → 各自向量化 → 存进向量数据库；检索时只在库里找最相近的片段。
检索质量决定答案质量：检索到无关片段，模型会被带偏；检索准，答案才有据可依。
🧩 向量化（Embedding）用模型把文本转成一串固定长度的数字向量；语义相近的文本向量也相近，便于"按意思找"而非"按字面匹配"。
📐 相似度检索问题向量与库中每个片段向量比距离（余弦 / 内积），取最近的 k 个拼回上下文。
🗂 切块与索引长文档切成小段分别向量化并建立索引，检索又快又准；切得太碎或太大都会掉质量。
🔁 生成（Generate）大模型拿到"问题 + 检索片段"后生成答案，可显式引用证据，减少凭空编造。

代表方法：RAG（Lewis et al., NeurIPS 2020）首次把"先检索、再生成"做成统一框架；DPR（Karpukhin et al., EMNLP 2020）提出稠密向量检索，比传统关键词检索更懂语义；REALM（Guu et al., 2020）把检索直接融进预训练，让语言模型"开书答题"。

3 一个具体应用场景

企业内部"知识助手"（如用 RAG 搭的客服 / 文档问答）。

  1. 建库：把公司产品手册、FAQ、历史工单切块并向量化，存进向量库；
  2. 提问：员工问"XX 型号怎么退货"，问题被向量化；
  3. 检索：向量库返回最相关的退货政策片段（Top-k）；
  4. 生成：大模型结合这些片段给出带出处的准确答复，而不是凭"训练记忆"瞎猜。

没有 RAG，模型要么答不出公司内部信息，要么编造一条看似合理的错误流程——RAG 让它"有据可查"。

4 易混淆与使用边界

对比对象关键区别
vs 纯参数记忆（模型自己背）参数记忆是训练时固定的通用知识，不知道你的最新/私有资料；RAG 用外部库补上"实时、专属"的部分。
vs 传统关键词搜索关键词搜索看"字面匹配"；向量检索看"语义相近"，能找回换了个说法但意思一样的文档。
vs Agent 记忆（见另一卡片）记忆是 Agent 自己存下的个性化经历；RAG 是面向通用外部知识库的检索增强，二者常配合：记忆存"你是谁"，RAG 取"世界知识"。

不该做的事：以为"检索越多越准"——塞一堆无关片段只会干扰模型；不维护知识库（过期文档照样被检索）；切块太随意导致语义断裂；用错 embedding 模型使"相似"失真。

5 自测问题（先想再点开）

Q1：RAG 里的 "R"（Retrieval）发生在哪一步？
在生成答案之前：先把与问题最相关的外部文档片段检索出来，再和原问题一起送进大模型。
Q2：为什么要把文本转成向量（embedding）？
让"意思相近"的文本在向量空间里也离得近，从而用相似度检索找回"换种说法但同义"的文档，比关键词匹配更语义化。
Q3：RAG 能完全消除"幻觉"吗？
不能。它显著降低凭空编造，但检索若出错/缺失，模型仍可能被带偏；知识库需保持准确、及时。
Q4：向量检索与关键词检索最大区别？
向量检索按"语义相似度"找，能跨表述；关键词检索按"字面匹配"，换说法就可能漏掉。
