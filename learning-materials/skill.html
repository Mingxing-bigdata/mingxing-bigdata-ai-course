1 我的解释（个人理解）

Skill = 把“某类任务怎么做才专业”沉淀成的一份说明书文件夹（核心是 SKILL.md，可附脚本与参考资料）。Agent 平时只知道它的简介，遇到匹配任务时才把说明书完整读入、照着执行——于是同一个通用 Agent 面对不同专业任务都能“立刻变得专业”，这套方法还能随仓库反复复用、共享给任何人。

2 核心机制 / 组成

skill-name/
├── SKILL.md      # ★ 技能说明书：frontmatter 元信息 + 分步做法（必备）
├── scripts/      #   可复用脚本（Python/Shell，可选，保证确定性执行）
├── references/   #   参考资料/模板（可选，按需读入，不占上下文）
└── assets/       #   图标、示例文件（可选）
🎯 description＝触发开关frontmatter 中写清“何时用、何时别用”，Agent 靠它判断是否加载
📥 按需加载（渐进披露）平时只暴露一小段 description；匹配成功才读 SKILL.md，用到什么再读什么
📋 正文＝稳定流程把“步骤＋规范＋自检清单”写成可执行方法，保证输出质量一致

3 一个具体应用场景

场景（本仓库的活例子）：把“如何学懂一个抽象概念”做成 concept-learner 这个 Skill。

  1. 你提出“帮我搞懂 XX 概念”；
  2. Agent 读到各 Skill 的 description，发现 concept-learner 匹配“概念学习”；
  3. 加载其 SKILL.md，按“澄清 → 一句话理解 → 拆机制 → 找案例 → 辨析 → 自测 → 查来源”的流程执行；
  4. 产出同构的概念学习卡（本仓库 learning-materials/ 下的资料就是这样生成的）。

换个新概念（如“数据倾斜”“布隆过滤器”），同一份 Skill 无需修改即可再用——这就是“沉淀复用”。

4 易混淆与使用边界

对比对象关键区别
vs 临时写一大段提示词提示词每次重写、容易漏；Skill 把最佳流程一次沉淀、反复复用、可版本管理、可随仓库共享。提示词像口头交代，Skill 像交给团队的 SOP 文档。
vs MCP / Function Calling（工具）工具是 Agent 的“手脚”（能做什么外部动作）；Skill 是“方法论”（怎么做才专业）。两者配合：Skill 规定流程，工具负责执行。
vs 知识库 / RAG知识库提供“事实数据”，Skill 提供“做事步骤”：一个告诉 Agent“知道什么”，一个告诉它“怎么做”。

不该做的事：一个 Skill 塞太多职责（应单一职责）；description 写太模糊（会导致漏用/误用）；Skill 里带的脚本要先审查再执行（它会获得真实权限）。

5 自测问题（先想再点开）

Q1：SKILL.md 的哪个字段决定 Agent“何时触发”这个技能？
frontmatter 的 description——写清适用场景与触发词，是“对号入座”的依据。
Q2：Skill 平时会一直占用上下文吗？
不会。平时只暴露短小的 description，匹配成功才按需加载正文与资源（渐进披露）。
Q3：Skill 和 MCP 工具的分工是什么？
工具＝执行外部动作的“手脚”，Skill＝规定专业流程的“方法论”，二者配合而非替代。
Q4：给“做 PPT”写一个 Skill，第一步最该写好什么？
description（何时用/何时别用/触发词），否则 Agent 可能根本不会在正确时机加载它。
