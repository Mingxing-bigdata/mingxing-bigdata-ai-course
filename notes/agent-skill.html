1 先搞懂：Agent（智能体）是什么？

Agent 是能够自主完成任务的 AI 系统：理解目标 → 规划步骤 → 调用工具 → 得到结果。

它不是"聊天机器人"，而是一个会"动手做事"的系统。业界公认的四要素：

🧠 大脑（LLM）大语言模型负责理解、推理、生成计划与内容
📋 规划（Planning）把复杂任务拆解成可执行的小步骤
🔧 工具（Tools）调用外部能力：搜索网页、执行代码、操作文件、调 API
🗂 记忆（Memory）保存上下文、中间结果，持续修正方向
📚 本节来源： Lilian Weng《LLM Powered Autonomous Agents》(Agent 经典长文) · LangChain 官方 Agents 概念 · OpenAI Agents SDK — Tools

2 Agent Skill：给智能体的"专项能力包"

Skill 是把"某类任务怎么做"沉淀成的一份能力包 —— Agent 遇到匹配任务时，按里面写好的流程执行，不必每次重新摸索。
类比理解
📖 给新员工的 SOP 手册不用从头教，照着流程就能做好
🧩 浏览器的插件按需加载，缺什么能力装什么
⚙️ 工人的专用工具把通用能力变成"专项专家"

一句话：Skill = 专业流程知识 + 可执行脚本。让通用 Agent 在特定领域立刻变得专业、稳定、可复用。

📚 本节来源： Claude 官方 Skills 文档（中文） · anthropics/skills 官方开源仓库 · 百度百科「Agent Skills」词条

3 一个 Skill 内部长什么样？

每个 Skill 是仓库里的一个独立文件夹，核心是 SKILL.md：

# 一个典型 Skill 的目录结构（以官方仓库示例为原型）
my-skill/
├── SKILL.md      # ★ 技能说明书：元信息 + 使用步骤（必备）
├── scripts/     # 可复用脚本（Python/Shell 等，可选）
├── references/  # 参考资料 / 模板（可选）
└── assets/      # 图标、示例文件等（可选）

其中 SKILL.md 的头部（Frontmatter）有两个关键字段：

---
name: my-skill        # 技能名（简短）
description: 当用户需要……时使用    # ★ description = Agent 的"触发开关"
---

# 使用步骤（正文）
1. …… 2. …… 3. ……
description 决定"何时触发"写清适用场景、触发词、不适用的情况，Agent 才能对号入座
正文决定"怎么做"分步骤、带规范与检查项，确保输出质量稳定
scripts 决定"自动化程度"把重复劳动写成脚本，一步执行
按需加载Skill 平时不占用上下文，匹配任务时才被读取——轻量高效
📚 本节来源： Claude 官方 Skills 文档（中文）— SKILL.md 规范 · anthropics/skills（17+ 个官方示例可参考）

4 Agent + Skill 的协作流程

用户提任务"帮我做张 PPT"
→
LLM 理解意图推理
→
匹配 Skill读各 description
→
加载该 SKILL.md按需读入
→
执行步骤+脚本产出结果
→
反馈用户完成

核心设计："会用的工具"(MCP/函数) 与 "会做事的方法"(Skill) 分离

5 上手建议与常见辨析（避坑）

✅ 写好 description包含：什么时候用 + 典型触发词 + 什么时候别用
✅ 聚焦单一职责一个 Skill 只做一件事，好匹配、好维护
✅ 正文写步骤像给同事的交接说明：步骤+规范+自检清单
✅ 附最小示例放一个可运行 demo，便于验证与学习
❓ Skill 和"每次都写一大段提示词"有什么区别？
提示词每次都要重写、容易遗漏；Skill 把最佳流程一次沉淀、反复复用，还能随仓库共享给他人。
❓ Skill 和 MCP / Function Calling（工具）是什么关系？
工具/函数是 Agent 的"手脚"（能做什么外部动作）；Skill 是"方法论"（这件事怎么做才专业）。两者配合：Skill 告诉流程，工具负责执行。学习材料常将 MCP 定义为工具连接协议。
❓ Skill 需要每时每刻都占着上下文吗？
不需要。Skill 采用按需加载：平时只暴露 description（很小），任务匹配成功才读取完整内容。
❓ 我自己能创建 Skill 吗？
可以。写一个文件夹 + 一个 SKILL.md 即可起步，参考官方仓库里的示例最快上手。
